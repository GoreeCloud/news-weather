# GoreeCloud News & Weather — Platform Integration Evaluation

## Status

Initial Development applicability evaluation. No integration listed here is implemented until source and validation evidence exist.

## Nine Integral Platform Systems

| System | Initial applicability | Direction |
|---|---|---|
| GoreeCloud Manager | Evaluate | Consider lifecycle/configuration visibility where applicable. |
| Privacy Shield | Applicable | Privacy controls, permission/data-minimization contracts, privacy-state presentation. |
| Wardveil Security | Applicable | Security contracts, protection evidence, safe external-content handling. |
| Everkeep | Evaluate / likely applicable | Preservation, recovery, portability, and application-state backup boundaries. |
| Glaze UI | Applicable | Current approved visual, interaction, responsive, and accessibility contract. |
| GoreeCloud Mesh | Evaluate | First-party coordination only where an approved contract adds real value. |
| GoreeCloud Identity | Conditionally applicable | Optional account-backed synchronization; basic use stays account-optional. |
| GoreeCloud Policy | Applicable | Governed policy decisions for permissions, data handling, security, and administration where required. |
| GoreeCloud Observability | Applicable | Privacy-bounded health and operational evidence without behavioral analytics. |

## Separately governed capabilities

- **GoreeCloud Sync** — conditionally applicable for optional synchronization.
- **GoreeCloud Location** — applicable when a current approved contract exists; manual location remains supported.
- **GoreeCloud Notify** — applicable to severe-weather and explicitly selected news notifications; never engagement reminders.
- **GoreeCloud Application Foundation** — evaluate current approved lifecycle/settings/packaging contracts.
- **GoreeCloud Feeds** — required news backend dependency.

## Rules

- Integration is contract-driven.
- Another product's private database is not an integration API.
- Documentation does not establish runtime conformance.
- Missing, stale, superseded, or unverified required integration blocks full platform-conformance claims.
- Stable qualification requires all nine systems to be evaluated and every applicable system to be implemented, current, validated, and accepted.
